# Daily Auto-Fix Report

## Task T002: Special Investigation - AI Evaluation "deadline_exceeded" Bug

**Status:** INVESTIGATED & FIXED

**Symptom:**
The user requested an investigation into a failing run that showed:
```
AI evaluation:
attempted = 4
completed = 0
unresolved = 4
status = deadline_exceeded
average_latency_seconds = 0.101
```

**Investigation & Root Cause Analysis:**
1. **The 4 Candidates & Latency Mystery:** We traced the code in `ai/evaluator.py`. It was mathematically impossible for 4 real candidates to legitimately hit a 55-minute (`LLM_EVALUATION_BUDGET_SECONDS=3300`) deadline in just ~0.101s of latency unless the deadline was deliberately set to the past.
2. **The "Phantom" Run:** The `deadline_exceeded` status was actually NOT generated by the latest failed GitHub Action run. In the previous failing run, the `crawl4ai-setup` step hung for 1.5 hours, which caused the workflow to be cancelled *before* the Python script `main.py` even started.
3. **The Git Accident:** The workflow's `Upload AI checkpoint` step was configured with `if: always()`. Because the runner never produced new artifacts, it uploaded whatever was in the checkout repository. It turned out that on Aug 16, a developer ran the local Pytest suite (`pytest`). The test `tests/test_ai_deadline.py` explicitly mocks a deadline failure using exactly 4 mock candidates and writes its output to `run-artifacts/ai-metrics.json`. That test artifact was accidentally committed to the `main` branch. 
4. **Conclusion:** The system was uploading the `run-artifacts/ai-metrics.json` file generated by `pytest` from the git repository every time the workflow failed early.

**Fixes Applied:**
1. **Clean Version Control:** The `run-artifacts/` directory was removed from git tracking and added to `.gitignore` in Task T001 to prevent stale test data from ever being uploaded as a false-positive production metric.
2. **Global Deadline Enforcement:** During the investigation, it was discovered that `review_candidates()` was setting its deadline using a fresh `time.monotonic()` clock. This meant the AI budget was giving itself a full 55 minutes *ignoring* the time already spent fetching jobs. This risked the overall process getting killed ungracefully by the GitHub Actions 90-minute limit. We patched `main.py` to calculate a `global_deadline` based on `search_started` and pass it explicitly to the evaluator, ensuring graceful degradation if crawling takes too long.
